## [1.0.0] - 2026-10-17

First release. Readiness, verification and open items: [`docs/release-1.0.md`](docs/release-1.0.md).

### Security

- Trusted Types enforced by the CSP, with one default policy that allows only this origin's
  service worker and build chunks as scripts.
- The production nginx configuration is tested with the whole e2e suite
  (`scripts/serve-nginx.sh`); header, caching and 404 checks in `e2e/security.spec.ts`.
- Security review in [`docs/security.md`](docs/security.md).

### Accessibility

- WCAG 2.2 AA audit ([`docs/accessibility.md`](docs/accessibility.md)): axe on every screen and
  dialog in both themes, reflow at 320 px, keyboard-only tracking, reduced motion.
- Fixed: stage cards overflowing on narrow screens, missing `main` landmarks (tracker, chart
  editor), missing `h1` (chart editor), photo corners that could only be dragged.

### Performance

- The pattern editor loads on demand; a startup bundle budget runs in CI. Open and tap latency
  budgets in `e2e/perf.spec.ts` ([`docs/performance.md`](docs/performance.md)).

### Added

- Local-only `SyncAdapter` (ADR-4) with the sync status in the settings; the app version is shown
  there too. An e2e test checks that progress survives an app update.
- M5 stages and projects: stages that continue the chart rows of an earlier stage (front and back
  after a split, layout changes from a row, "Zmiana układu" in the pattern editor), open-ended
  stages with a target length and a row estimate from the gauge (pattern gauge or the knitter's
  own), finishing and reopening a stage with the last chart rows shown, a next-stage button,
  row-counter stages for ribbing and plain sections, manual position entry ("Ustaw", shortcut G),
  project settings (name, own gauge), stage order, links from a pattern to its projects, and
  restoring a full backup with a preview that never overwrites newer work.
- Schema version 2 (additive) with a tested migration from frozen v1 files; backups are written
  and read by `@kt/core`.

- M4 import (`/import`, **Wzory → Rozpoznaj z PDF lub zdjęcia**): PDF (raster or vector charts), screenshots, scans
  and photos are read locally in a Web Worker; nothing is uploaded. Steps: optional photo
  straightening (drag four corners), legend review (each icon paired with its text and a library
  symbol, recognition re-run after a fix), verification of every chart next to the original (doubtful
  cells outlined, "next doubtful cell", quick fixes, keyboard), description review (sizes, chart
  sequence, stitch counts, marker; text from the same PDF or a second file) and creation of a normal
  pattern that opens in the editor. Upload limits: 25 MB, 30 pages, 40 megapixels.
- `@kt/importer`: grid detection, template classification with row segmentation and calibrated
  confidence, legend pairing and a Polish legend reader, description parser, pattern draft builder,
  crop & straighten. Synthetic test charts, PDFs and photos generated in the tests; the local
  `DROPS 246-2.pdf` acceptance test (skipped without the file) reports 0 cell differences for
  A.1–A.4.
- Library glyphs for 2/2 purl cables redrawn so the purl mark does not touch the cable line.

- M3 editor: pattern library (`/wzory`), pattern page (basics, sizes, charts with thumbnails,
  stages, the pattern's own legend numbers and wording, custom symbols, inline validation in
  Polish/English), chart editor (draw, select, move; palette and searchable symbol library; copy,
  cut, paste, fill, mirror with symbol direction swap, insert/delete rows and columns, resize;
  undo/redo; keyboard shortcuts; problem cells outlined), layout wizard (round/flat, rows and
  expected stitches per size, chart placements with partial repeats, start column and row, markers
  with section names, stitch-count table, live grid preview). New patterns can start a project or
  be exported right away.
- Core: chart editing operations, pattern authoring helpers, bounded editor history, localized
  diagnostic params.

- M2 tracker: canvas chart grid (`@kt/grid-renderer`: geometry, camera, pure scene builder,
  Canvas2D backend with a 256-px tile cache, level of detail, frozen header and row gutters, row
  keeper, stitch marker, hatched done cells), tap / eraser / undo / redo / complete row, keyboard
  shortcuts and a keyboard cursor, current row as text, legend from the same glyphs, view controls
  (cell size, rows shown, fit width/section, veil), Wake Lock, light/dark/system theme, Polish and
  English UI.
- Local-first storage (Dexie/IndexedDB with an in-memory fallback and warning), persistent-storage
  request, backup export, pattern file import with validation report, per-project "chart in plain
  knit" variant, onboarding sample pattern, service-worker update prompt.
- Design direction and tokens (`docs/design.md`), screenshot tour script, e2e tests for the
  file → tap → reload → offline scenario, shortcuts, WS rows, axe on every screen, and a 500 × 300
  rendering budget test.

- M1 domain core (`@kt/core`): zod schemas for patterns and projects, built-in symbol library
  (knit/purl, increases, decreases, bind-off, no-stitch, 12 cable crossings with derived stitch flow
  and DROPS number mapping), chart parsing, stage layout with partial horizontal repeats, independent
  vertical repeats, markers and sections, per-project chart replacement, progress engine for round and
  flat work (WS rows reversed and inverted), undo/redo reducer, text instructions per row,
  validation (structure, stitch-count chain, stitch-flow lint, partial repeats cutting cables, WS
  symbols, references), versioned pattern files with migrations. Unit, property-based and local
  golden tests.
- `docs/pattern-format.md`: pattern file format and diagnostics.
- Phase 0 analysis, requirements, risks and ADRs (`docs/00-analysis.md`, `docs/adr/`).
- M0 project skeleton: pnpm monorepo (`@kt/core`, `@kt/grid-renderer`, `@kt/importer`,
  `@kt/test-fixtures`, `@kt/web`), strict TypeScript, ESLint/Prettier, husky, lint-staged,
  commitlint, Vitest with a coverage gate, Playwright on four viewports with axe, a PWA shell with an
  offline service worker, a Docker image (nginx-unprivileged with CSP), compose profiles, a GitHub
  Actions CI, Renovate and release-please configuration, and a forbidden-content guard.
